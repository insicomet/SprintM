# Базовый отчёт Excel-паритета

## Сценарий

Базовый сценарий — «B · Курган, 15×42, h4,5, γn=0,8».

**Статус: provisional.** Зафиксированные результаты находятся в
`scripts/oracle/expected/baseline-b.json`, но независимое происхождение всех
значений в текущем workspace подтвердить нельзя.

Проверка запускается командой:

```powershell
npm.cmd run check:parity-baseline
```

Она сравнивает цепочку подбора и итоги ведомости с сохранёнными результатами
Excel. Файл фактического результата создаётся в игнорируемом каталоге
`scripts/oracle/work/`.

## Происхождение ожидаемых значений

- В комментариях `hypothetical.test.ts` указано, что подборщик и ведомость
  пересчитывались LibreOffice через `calculateAll()`.
- Имена, по которым runner ожидает книги: `engine_src.xlsx` и `bom_src.xlsx`.
  Исходные имена файлов, их SHA-256 и сами книги сценария B отсутствуют.
- Подборщик: лист `вывод`, ячейки `D3`, `D22`, `D23`, `D28`, `D33`, `D34`,
  `D35`, `E52`, `D57`, `E24`.
- Ведомость: лист `12м`, ячейки `F32`, `F44`, `F70`, `F81`, `F100`, `F114`,
  `F147`, `F82`, `F148`, `F149`, `F151`, `F154`.
- Входы полностью записаны в `baseline-b.json`: Курган, 15×42×4,5 м,
  `γn=0,8`, кровля СП 150, стеновая панель 100, двое ворот 3,5×3,5,
  одна дверь 1×2, снегозадержание включено.
- Подтверждения пересчёта через Microsoft Excel нет. Заявлен пересчёт через
  LibreOffice, но машинный лог или подписанный отчёт пересчёта не сохранён.
- Числа baseline перенесены из текущего `hypothetical.test.ts`. Без исходных
  книг невозможно доказать, что они не были ранее получены либо скорректированы
  по TypeScript-коду.

Для статуса `verified` нужны обе исходные книги, их контрольные суммы,
сохранённый лог пересчёта и машинный отчёт сравнения.

## Результат snapshot-проверки

- Цепочка подбора со snapshot: 0 расхождений.
- Итоги ведомости со snapshot: 0 расхождений.
- Допуск денежных итогов: максимум 0,005 руб. или 1e-9 от значения.

## Известные расхождения и ограничения

1. В шаблоне ведомости `J14` постоянно содержит уклон 15°, тогда как подборщик
   использует 6° для пролёта 24 м. Оракул следует правилу подборщика.
2. В проекте 22316 подтверждена ошибка длины обрамления окна в исходной
   ведомости. Приложение использует исправленное правило и поэтому дороже файла
   на 4 076,54 руб. по каркасу с накладными.
3. Автоматический расчёт перемычек окон не перенесён; для сценариев с окнами
   масса `вывод!E68` вводится из подборщика.
4. Формулы профлистовой обшивки не подтверждены реальным профлистовым объектом.
5. Полный пересчёт исходных книг требует локальных `engine_src.xlsx`,
   `bom_src.xlsx`, LibreOffice и макроса `Module1.xba`. Эти книги не входят в Git.

Сохранённый provisional baseline является только регрессионной проверкой уже
полученного результата, а не доказательством Excel-паритета и не заменой
повторной инженерной приёмки исходных книг.
